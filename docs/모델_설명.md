## 1. 엑셀 함수 ↔ 프로그램 대응

엑셀에서 쓰던 물성 함수는 `turbochiller/props.py` 가 그대로 받는다.

| 엑셀 | 프로그램 |
|------|----------|
| `PropsSI("H","T",T+273.15,"P",P*1000,ref)/1000` | `props.h_tp(ref, T, P)` |
| `PropsSI("P","T",T+273.15,"Q",1,ref)/1000` | `props.p_sat(ref, T, q=1)` |
| `PropsSI("S","T",T+273.15,"P",P*1000,ref)/1000` | `props.s_tp(ref, T, P)` |
| `PropsSI("T","S",s*1000,"P",P*1000,ref)-273.15` | `props.t_sp(ref, s, P)` |
| `PropsSI("T","H",h*1000,"P",P*1000,ref)-273.15` | `props.t_hp(ref, h, P)` |
| `refprop("H",ref,"TQ","MKS",T+273.15,0)` | `props.h_sat(ref, T, 0)` |

단위는 엑셀과 같은 공학 단위(°C, kPa, kJ/kg)를 쓴다.

> 2단 R1234ze 시트만 REFPROP 애드인을 썼고 나머지는 CoolProp 을 썼다.
> 이 프로그램은 전부 CoolProp 으로 통일했다. 두 라이브러리의 차이 때문에
> 2단 R1234ze 결과는 엑셀과 0.1% 안쪽에서 미세하게 다르다.

## 3. 엑셀에서 고친 부분

### 3.1 2단 흡입 혼합 — 온도 평균 → 엔탈피 평균

1단 토출 증기(ṁ)와 서브콘덴서 증기(x·ṁ)가 섞여 2단으로 들어간다.
섞이는 것은 **에너지(엔탈피)** 이지 온도가 아니다.

```
엑셀 (1234ze 시트)  T3 = (1−x)·T2 + x·T6     ← 질량가중 평균도 아니다
엑셀 (134a 시트)    T3 = (T2 + x·T6)/(1+x)   ← 질량가중이지만 온도 기준
이 프로그램         h3 = (h2 + x·hg(Tm))/(1+x),  T3 = T(h3, Pm)
```

비열이 온도에 따라 변하므로 온도 평균은 근사다. 다만 온도차가 작아서
결과 차이는 크지 않다 (위 예에서 2단 토출온도 기준 0.1~0.2°C).

두 시트의 식이 서로 다른 점도 참고할 것. `ExcelCompat(temperature_mixing=True)`
는 134a 시트 쪽(질량가중)을 따른다.

### 3.2 2단 응축 열량 — (1+x) 누락

엑셀 2단 시트: `Qc = ṁ₁ · (h4 − h5)`

응축기를 지나는 냉매는 1단 유량이 아니라 **1단 + 중간단 = (1+x)·ṁ₁** 이다.
1234ze 시트 기준으로 **20% 과소평가**된다 (x = 0.2).

이 프로그램은 `Qc = (1+x)·ṁ₁·(h4 − h5)` 로 계산한다.
응축기 용량 산정과 2차측 유량·UA 가 전부 이 값에서 나오므로 영향이 크다.

### 3.3 중간단 유량비 x — 손으로 지정 → 에너지 밸런스

엑셀은 x 를 0.2 (1234ze) / 0.1 (134a) 로 고정해 두었다.
이코노마이저는 아래 에너지 수지를 만족해야 한다.

```
(1+x)·h5 = x·hg(Tm) + h7      →      x = (h5 − h7) / (hg(Tm) − h5)
```

x 를 임의로 정하면 이 수지가 깨진다. 실제로 1234ze 조건에서
x = 0.2 를 쓰면 **에너지 수지가 약 4% 어긋난다.**

`subcond_mass_ratio` 를 비워 두면(기본값) 위 식으로 계산하고,
그때 `energy_balance_error` 는 0 이 된다.

### 3.4 중간압 — 고정값 → √(P1·P2)

엑셀 2단 시트에는 `√(P1P2)` 를 계산해 둔 셀(G19)이 있지만 실제로 쓰지는
않고, 서브콘덴서 온도를 32°C / 30°C 로 고정해 놓았다.

중간압을 기하평균으로 잡으면 두 단의 압축비가 거의 같아져서
전체 단열효율이 좋아진다. 부분부하(IPLV)처럼 응축온도가 바뀌는 계산에서는
고정값을 쓰면 **중간온도가 응축온도보다 높아져 계산 자체가 불가능해진다.**

그래서 `t_subcond` 기본값은 비워 두었고(자동), 필요하면 직접 지정할 수 있다.

## 4. 모델의 한계 — 알고 쓸 것

- **배관 압력손실을 등온으로 본다.** 엑셀과 같은 방식이다. 실제 배관 손실은
  등엔탈피에 가까우므로 0.05% 정도의 에너지 수지 오차가 생긴다.
- **단열효율이 입력값이다.** 압축기 성능곡선이 아니라 고정 효율을 쓴다.
  부분부하 효율은 `standards.default_part_load_efficiency` 의 가정값이므로,
  실측 성능곡선이 있으면 그 함수를 바꿔 쓸 것.
- **IGV·디퓨저·서징 한계를 다루지 않는다.** 터보 압축기의 서징/초킹 판정은
  들어 있지 않다.
- **압축기 내부 설계는 다루지 않는다.** 임펠러·확산기 형상, 손실 모델,
  성능맵은 범위 밖이다. 별도 프로그램으로 만든다 (README 의 '범위' 참고).
- **`규격` 시트의 미확정 항목은 그대로 둔다.** 수냉 approach, 난방모드
  approach 는 원본에도 "확인 필요" 로 적혀 있다. 난방(heat pump) 모드는
  아직 구현하지 않았다.
