# 엑셀 계산서 — 애드인 없이 혼자 도는 판

REFPROP·CoolProp 애드인 없이, **엑셀 파일 하나만으로** 사이클이 계산된다.
물성표를 시트에 심어 두고 보간으로 꺼내 쓰기 때문이다.

```bash
python -m excel.make_all          # excel/출력/터보냉동기_사이클계산_Rev6.xlsx
```

냉매 4종(R1234ze(E) · R134a · R1234yf · R513A)이 **한 파일 안에** 들어 있다.

## 리비전

파일 이름과 `[계산]` 시트 머리말에 **Rev 번호**가 찍힌다. 고칠 때마다
`excel/version.py` 의 `REVISION` 을 올린다. 이름이 같아 새 파일을 받고도
옛 파일을 열어 보는 일이 실제로 있었다.

| Rev | 바뀐 것 |
|-----|---------|
| 6 | 온도·건도 숫자를 선 위에 직접 적고, 등엔트로피선·등비체적선을 넣었다 |
| 5 | 등온선·건도선을 넣고 포화 돔을 임계점까지 닫았다 |
| 4 | 수식 길이 한도 초과로 압축동력이 음수로 나오던 오류를 고쳤다 |
| 3 | P-h 선도가 인쇄 범위 밖으로 잘려 나가던 것을 고쳤다 |
| 2 | 냉매 4종을 한 파일에 담고 선도와 결과 요약을 넣었다 |
| 1 | 애드인 없이 혼자 도는 계산서 (냉매별 파일) |

## 쓰는 법

`[계산]` 시트 하나만 보이고, 나머지는 숨겨 두었다.

1. **B4 칸에서 냉매를 고른다** — 칸을 누르면 목록이 나온다
2. **파란 글씨 칸만 고친다** — 나머지는 전부 수식이다
3. 맨 위 **■ 결과** 와 오른쪽 **P-h 선도** 가 바로 따라온다

```
냉매        [R1234ze(E) ▼]
■ 결과      COP · 소비전력 · 냉동톤당 전력 · 체적유량 · 압축비 · 토출온도
■ 입력      파란 칸
■ 운전조건  증발·응축·중간압 (입력에서 자동)
■ 상태점    9 점 (온도·압력·엔탈피·밀도)
■ 압축 계산 등엔트로피 → 실제 헤드 → 이코노마이저 유량비
■ 계산 결과 유량 · 동력 · COP · 응축열량 · 에너지 수지 오차
```

**에너지 수지 오차**(Qc − Qe − W)가 0 에서 멀어지면 입력값 조합이 말이 안
된다는 뜻이다. 정상이면 0.05% 쯤 나온다.

### 숨어 있는 시트

보기만 복잡해지니 숨겼다. 들여다볼 일이 있으면 시트 탭에서 숨김 해제하면 된다.

| 시트 | 내용 |
|------|------|
| `조회` | 물성표를 뒤져 보간하는 곳. 중간값(포화온도·과열도·행·열)을 펼쳐 두었다 |
| `설정` | 냉매별 표 위치. B4 를 바꾸면 이 표를 통해 참조가 옮겨간다 |
| `물성_포화` | 포화 물성표 (T, Psat, hf, hg, sf, sg, ρg) |
| `물성_h` / `물성_s` / `물성_밀도` | 과열증기 표 |
| `차트데이터` | P-h 선도용 좌표 |

## 냉매를 어떻게 한 파일에 담았나

냉매 4종의 표를 옆으로 나란히 붙여 놓고, `[설정]` 시트에 **각 냉매의 표가
몇 번째 행·열에서 시작하는지**를 적어 두었다. B4 를 바꾸면 모든 조회 수식이
그 위치로 옮겨간다.

```
=INDEX(물성_h!전체, 행, 열 + 열오프셋)
                          └─ B4 로 정해지는 값
```

범위를 `INDEX(열,시작):INDEX(열,끝)` 로 잡아 **휘발성 함수(OFFSET·INDIRECT)를
쓰지 않았다**. 그래서 파일을 열어 둬도 느려지지 않고, 폰 엑셀 앱에서도 돈다.

## P-h 선도

`[계산]` 시트 오른쪽(F6 부터)에 들어 있다. 압력축은 로그 눈금이다.

| 선 | 내용 |
|----|------|
| 포화선 | 포화 돔. 임계점에서 닫힌다 |
| 등온선 | −20 / 0 / 20 / 40 / 60 / 80 °C — 과냉액 → 2상(수평) → 과열증기 |
| 건도선 | x = 0.2 / 0.4 / 0.6 / 0.8 |
| 등엔트로피선 | 포화증기선 위에서 출발해 올라간다. 압축기가 지나는 길 |
| 등비체적선 | 흡입 비체적 = 압축기 크기 |
| 사이클 | 상태점 1→2→3→4→5→6→7→8→9 (파란 굵은 선) |

축은 h 100~500 kJ/kg, P 10~10000 kPa 로 **고정**했다. 냉매를 바꿔도
축이 출렁이지 않아야 선도끼리 눈으로 비교가 된다.

### 숫자는 선 위에 적는다

**온도와 건도는 선 옆에 직접 적는다.** 범례로 빼면 어느 선이 몇 도인지
알아볼 수가 없다. 글자가 서로 겹치지 않는 자리는 `_place_labels` 가
고른다 — 선마다 '여기면 된다' 하는 후보 구간을 받아 두고, 이미 놓은
글자에서 떨어진 자리를 집는다. 그래서 냉매를 바꿔도 안 겹친다.

구현은 **한 점짜리 계열에 '계열 이름 표시'를 켜는** 방식이다. 점마다
이름표를 지정하는 방식(`dLbl idx=`)은 LibreOffice 가 무시하고 모든 점에
값을 찍어 버린다.

글자가 길어 숫자와 겹치는 등엔트로피선·등비체적선만 아래쪽 범례에
남겼다.

### 모든 계열에 smooth=0 을 적는다

`<c:smooth>` 를 빠뜨린 계열이 하나라도 있으면 **LibreOffice 는 그걸 차트
전체에 적용해** 사이클을 둥근 덩어리로 뭉갠다. 등온선도 꿈틀거린다.
이름표 계열까지 빠짐없이 `smooth = False` 로 둔다.

### 보조선은 왜 미리 계산했나

등온선·건도선·포화 돔은 **냉매만 정해지면 결정된다**. 운전조건과는
상관이 없다. 그래서 엑셀 수식으로 매번 풀지 않고, `excel/chartlines.py`
가 CoolProp 으로 미리 계산해 숨은 `[선도데이터]` 시트에 심어 둔다.
엑셀은 고른 냉매의 블록을 `[차트데이터]` 로 베껴 오기만 한다.

곡선마다 점 개수를 60 으로 똑같이 맞췄다. 엑셀 차트는 참조 범위를
고정해 두어야 해서, 냉매를 바꿔도 길이가 변하면 안 되기 때문이다.

### 혼합냉매 돔 꼭대기

R513A 는 임계점 근처에서 CoolProp 의 밀도 풀이가 깨진다
(`critical point finding routine found 2 critical points`). 임계온도
4.4 K 아래까지가 한계라 돔 꼭대기가 뾰족하지 않고 평평하게 닫힌다.
없는 값을 지어내 메우지 않았다. 운전 범위는 임계점보다 45 K 아래라
쓰는 데 지장이 없다. 순수냉매(R1234ze·R134a·R1234yf)는 임계점까지
정확히 닫힌다.

### 숨은 시트와 차트

보조선 데이터는 숨긴 시트에 있다. 그래서 차트의 **'숨겨진 행과 열에
데이터 표시'** 옵션(`plotVisOnly`)을 꺼 두었다. 켜져 있으면 숨은 시트의
값을 빼고 그리느라 선이 통째로 사라진다.

## 표 구조 — 왜 '과열도 × 압력' 인가

압력마다 포화온도가 달라서, 온도를 그대로 행으로 쓰면 표가 들쭉날쭉해진다.
행을 **과열도**(포화온도로부터 몇 도 위인가)로 잡으면 모든 압력에서 행이
가지런해져 보간 수식이 단순해진다. 냉매를 여러 종 담을 수 있는 것도
행이 전부 같은 과열도를 쓰기 때문이다.

```
        압력 →
과열도   61kPa   85kPa   ...   3471kPa
  ↓
 0 K     (포화증기)
 2.5 K
 5 K
```

## 왜 애드인이 필요 없나

물성표를 미리 계산해 시트에 넣어 두었다. 그래서

- **동료 PC에 아무것도 깔 필요가 없다** — 파일만 보내면 된다
- **폰 엑셀 앱에서도 열린다** — 오프라인으로
- 라이선스 문제가 없다

## 정확도

표 보간이라 미세한 오차가 있다. 실제로 재 보았다.

| 항목 | 오차 |
|------|------|
| 포화압력·포화 엔탈피 | 0.000% |
| 과열증기 h·s·밀도 | 0.003% 이하 |
| **최종 COP·축동력** | **0.13% 이하** |

시험 측정 불확도가 이보다 훨씬 크다. 실무에서 문제 되지 않는 수준이다.

## 습압축 처리

냉매에 따라 등엔트로피 압축 후가 **포화영역 안**으로 들어가는 경우가 있다
(R1234yf 가 그렇다). 과열표에는 그 값이 없으므로, 건도를 구해 포화액과
포화증기 사이를 비례 배분한다.

`[조회]` 시트 오른쪽 끝에 `과열` 인지 `습압축 (건도 0.998)` 인지 적힌다.

## 수식 길이 — 엑셀의 숨은 한도

엑셀은 **한 칸의 수식이 8192자를 넘으면 그 수식을 조용히 버린다.**
오류 표시도 없이 값만 0 이 된다. LibreOffice 에는 이 한도가 없다.

실제로 Rev 3 까지 등엔트로피 엔탈피 수식이 8333자였다. 리브레에서는
네 냉매 모두 멀쩡히 통과했지만, 엑셀에서 열면 압축동력이 음수로 나왔다.
**리브레로만 검사해서는 절대 못 잡는 종류의 오류다.**

그래서 지금은

- 긴 수식은 중간값을 옆 칸(`[조회]` 시트 L~Q)으로 빼서 짧게 나눈다
- `build_workbook` 이 저장 전에 길이를 재서, 한도를 넘으면 **파일을 아예
  내보내지 않는다**
- 테스트가 길이와 중첩 한도를 본다

현재 제일 긴 수식은 3459자다.

## 검증

`tests/test_excel.py` 가 이 파일을 **LibreOffice 로 실제 계산시킨 뒤**
파이썬 엔진(CoolProp) 과 숫자를 맞춰 본다. 냉매 4종 모두, B4 를 바꿔
가며 돌린다.

원본 엑셀의 진짜 문제는 '엑셀이라서' 가 아니라 **검증이 없어서** 였다.
응축 열량 20% 과소평가가 오래 숨어 있었던 것도 그래서다.
수식을 고치다 깨뜨리면 이 테스트에서 걸린다.

```bash
pytest tests/test_excel.py
```
